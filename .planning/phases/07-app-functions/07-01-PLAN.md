<objective>
The 34 names of `finance`: the money functions a program can call. They are
the cleanest group of the phase -- every one has a published syntax string and
every one takes its arguments rather than reading an app's state -- which is
why they go first.
</objective>

<design>
The interpreter implements none of these, so the batch comes before the
writing, as it did for every group of Phase 6 without coverage.

**Every call goes inside `EXPR`.** Phase 6 paid four rounds of the user's
keypresses to learn that a call the compiler cannot read has the whole program
refused, and that a string cannot be refused at compile time. Nothing in this
phase is sent bare.

**Two families invert one equation each, and that is worth measuring rather
than describing.** `TvmFV`, `TvmIPYR`, `TvmNbPmt`, `TvmPMT` and `TvmPV` solve
the same time-value-of-money relation for a different unknown; so do the five
`BrkEv` names. One consistent set of arguments run through the family should
come back consistent -- feed `TvmPV` what `TvmFV` answered and the original
value should return. That cross-check is the same kind of evidence as
squaring `SIN` and `COS` and adding in Phase 6, and it is stronger than any
single row, because it is the calculator agreeing with itself.

`Depreciate` takes a method as its first argument and `CashFlow*` take a list
of flows. Those are the two shapes in this group that are not plain numbers,
so each gets one call that establishes the shape before anything is written
about it.
</design>
