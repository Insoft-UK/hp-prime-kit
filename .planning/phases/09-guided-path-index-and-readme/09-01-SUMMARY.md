# Plan 01 summary: the index a model loads first, and no example left unrun

## What was built

- **`docs/llms.txt`**, generated by `hpprime docs`. A header on the four
  labels, on `names.tsv` as the place a name's existence is looked up, and on
  how to cite; then a section per topic page, most used first, with each fact
  as its identifier linked to its anchor and its heading; then a section per
  group, with each entry as its name linked to its file and its summary.
  **74,939 bytes** for 598 entries and 117 facts, against a budget of 100,000
  that the check enforces on what would be generated, so a page not yet
  regenerated cannot hide the growth. It is stale-checked like the other
  generated pages, and its links and its pointers to the layer above are
  checked like any page of the documentation.
- **The check for examples nobody ran.** An example with no stored answer has
  to be `*no value*`, labelled `G2`, or one the interpreter actually ran.
  Anything else fails `hpprime docs --check`. On the documentation as it is,
  it reports nothing, which is what it is there to keep.
- **`--relabel` moves `unverified` as well as `HP help`** to `emulator` where
  the stored answer agrees. `G2` never moves.
- **21 examples relabelled** in ten entries -- `CASE`, `CONTINUE`, `DIM`,
  `IF`, `IFERR`, `INSTRING`, `LOCAL`, `REPEAT`, `RETURN`, `WHILE` -- and the
  prose of eight of them corrected to match.
- **Tests.** `test_reference.py` from 26 to 30: the index lists every entry
  and fact within its budget, and three breaks it has to catch -- an example
  nobody has run, the index edited by hand, a summary long enough to pass the
  budget. `test_examples_run.py` from 45 to 47: an `unverified` example the
  emulator confirms is relabelled, and one it contradicts keeps its label.
- `format.md` and `tools.md` state the new rules.

## What this turned up

**A fact that was measured and never written down.** Plan 05-01 put
`LOCAL za := 2, zb := 3; RETURN za + zb;` into its batch precisely to settle
`ppl.locals-initialised-one-line`. The batch ran, stored 5 on 2026-09-12, and
the fact stayed `unverified`, listed as open in the verifications of both
Phase 5 and Phase 6. It is `emulator` now, and says that more than two
initialised on one line has not been run, since the tutorial it cites wrote
three.

**Two entries contradicted a measured fact.** `IF` and `WHILE` said a single
`=` is not a comparison, where
[ppl.equality-operators](../../../docs/topics/ppl.md#ppl.equality-operators)
measured the opposite on the same day. Both now point at the fact, and
`WHILE` says the measurement was made in the test of an `IF`, not of a
`WHILE`.

**Claims that rested on an example now say what the example is.** `CASE`,
`CONTINUE`, `IFERR`, `REPEAT` and `WHILE` label `emulator` the sentence each
relabelled example supports, and `LOCAL` does for a local starting at 0.
`INSTRING` and `LOCAL` no longer say their examples wait for a batch. `CASE`
gained a sentence it lacked: whether the tests after a true one are still
evaluated has not been measured, which its old wording had implied was known.

**The test for uncovered examples needed an answer on file.** It added an
example that neither the interpreter nor any batch had run, which the new
check rightly refuses. The copy now stores an answer for it, so the test still
proves what it is for: uncovered is a note, not a failure.

## Deviations

- **The index is larger than the context estimated**: 74,939 bytes against
  69 KB. The estimate counted entry and fact lines only; the file also carries
  its header and a line per topic page and per group page. The estimate for
  the complete reference moves from 82,000 bytes to about 85,000, still under
  the budget.
- **Two uses of "this kit" went early**, in `INSTRING`'s evidence and in the
  fact, because those sentences were being rewritten anyway. The other 37
  pages are plan 09-02's.
