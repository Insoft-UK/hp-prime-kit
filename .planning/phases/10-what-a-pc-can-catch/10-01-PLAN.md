# Plan 01: the compile session, and the list of every fact

The context was approved by the user on 2026-09-25, with its three
decisions, its nine candidate checks and the compile session.

## 1. The compile session

`hpprime examples --compile`, as in 08.1-04: the programs below go on
`Prime_1` with the controls `ZCOK` and `ZCBAD`, the person presses `Check`
on each in the printed order, and each file says whether it compiled by its
compiled block. `HPKDOC` then calls every one, so a program that compiles
and fails when it runs is told apart from one that answers.

| Program | Fact | Question |
|---|---|---|
| `ZQGK1` | `ppl.getkey-no-parentheses` | does `GETKEY()` with parentheses compile, and answer? |
| `ZQGK0` | `ppl.getkey-no-parentheses` | `GETKEY` without them, the form measured on a G2, on this emulator |
| `ZQMU1` | `ppl.mu-zero-spelling` | `Inference.μ₀` with GREEK SMALL LETTER MU, U+03BC, in source |
| `ZQMU2` | `ppl.mu-zero-spelling` | the same with MICRO SIGN, U+00B5 |
| `ZQEP` | `ppl.no-end-keywords` | `ENDPROC` closing a function, as `ENDFUNC` was tried |
| `ZQX3` | `ppl.export-initialised` | 3 initialised variables in one `EXPORT` |
| `ZQX5` | `ppl.export-initialised` | 5 |

`μ₀` is written with the Inference app's name in front, so that the app rule
cannot be what refuses it
([apps.qualified-names](../../../docs/topics/apps.md#apps.qualified-names)).

**What each answer does.** `GETKEY()` refused: `getkey-parentheses` is an
error; compiled and answering: no rule, and the fact says both forms work.
The Greek mu refused and the micro sign answering: `mu-zero` is an error,
and `unknown-name` stops flagging the micro sign. `ENDPROC` refused:
`single-end` makes it an error as it did `ENDCASE` and `ENDFUNC`. 3 and 5
compiling: `export-multiple` stays quiet below 7 on measurements rather than
on the ones around them.

## 2. The list

For each of the 122 facts, one or more of the four answers in the context:
a lint rule, a command, nothing to catch, or not from a PC. The data goes in
`hpkit/lint.py`, beside `FACTS`: a table from fact to answer, with the rule
or command and its test, or the reason. `hpprime docs` writes it into
`docs/tools.md`, and a test in `tests/test_lint.py` fails if a fact has no
line, a line names a fact that does not exist, a rule named is not a rule,
or a command's test does not exist.

A command counts only with a test that would fail if the command stopped
doing it; where there is none, the plan adds it or the fact is not counted
as caught.

**The candidate checks enter the list as "a lint rule, to write"**, and the
list is shown to the user before plan 02 writes any of them.

## What this plan does not do

It writes no new rule. It changes the linter only where the session's
answers settle an existing rule (`single-end` on `ENDPROC`, `unknown-name`
on the micro sign).
