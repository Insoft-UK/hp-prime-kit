<design>
Each entry states HP's syntax, what it draws, which grob it draws into, and
the facts it depends on. Where a command answers a value as well as drawing --
`TEXTOUT_P` gives back the x it finished at, `GROBW` and `GROBH` answer a
size, `GETPIX` a colour -- that value is an example like any other and goes to
the emulator. Where it answers nothing useful, the entry says: "its result is
the screen, so there is no answer to record", which is the form criterion 2
allows.

The `_P` pairs are two entries, not one: the difference between drawing in
pixels and in the current window is exactly the kind of thing a model gets
wrong, and one entry covering both would hide it.
</design>
