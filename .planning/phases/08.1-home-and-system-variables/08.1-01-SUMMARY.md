# Plan 01 summary: Home's settings, the system's, and four open questions

## What was run

One batch of 71 calls on the Virtual Calculator 2.4, build 2025-09-15, on
2026-09-24, the user pressing the keys. All 71 answered or refused as rows:
none unreadable, none kept against a stored row. It was the first real run of
Phase 9.1's harness.

## What was built

- **20 entries**: the nine Home settings, the nine of the system, `Ans`, and
  `GET` in a folder of its own, `other`, which the list and its extractor now
  give it. Each says what it holds on a reset calculator, whether a program
  can set it, and, for the Home settings, what setting it changes.
- **A new fact**,
  [ppl.names-ignore-case](../../../docs/topics/ppl.md#ppl.names-ignore-case),
  `emulator`: `alog(2)` and `Alog(2)` answer 100, `xpon(1000)` answers 3.
- **`ppl.one-based` rewritten from the rows**, with a table of what a 0 does
  where it goes.
- **`MOD`, `NTHROOT`, `ALOG`, `XPON` and `STRING`** carry the new rows and
  what they say. 13 of them run through the interpreter and agree: 107
  examples run on the PC, from 94.

## What the rows said

- **A list read at 0 answers its last element, and assigning at 0 appends.**
  `{10,20,30}` gave 30, and became `{10,20,30,40}`. A matrix read at 0 is
  an error. So `L(0)` is not an error at all, which this repository said
  outright until 2026-09-23 and then marked as unmeasured, and for somebody
  coming from Python it is worse than an error: the last element, silently.
- **`MOD` binds like `*`, left to right, and its remainder takes the sign of
  the divisor.** `9 MOD 4 + 100` is 101; `2 * 7 MOD 4` and `9 MOD 4 * 2` are
  both 2; `2^3 MOD 5` is 3; `-9 MOD 4` is 3. `9 MOD (-4)` is −3, where HP's
  help promises a Euclidean remainder, which would be 1.
- **`NTHROOT` binds tighter than `*`**: `2 * 3 NTHROOT 8` is 4. An odd root
  of a negative is real, `3 NTHROOT (-8)` being −2; an even one is refused.
- **The calculator ignores case in a command's name**, as the linter had
  assumed since Phase 2.
- **`STRING` follows Home's format**: with `HFormat` 1 and `HDigits` 2,
  `STRING(1/3)` is `"0.33"`. With `HAngle` 1, `SIN(90)` is 1 in the same
  row. With `HComplex` 1, `(-4)^0.5` is `2*i` where at 0 it is refused.
- **`Bits` clips rather than wraps**: at 8 bits, `R→B(300)` is `#FFh`.
- **`EXPR` in a program does not move `Ans`**, and `TOff` is a based
  integer, 300000, which refused to be set to 300.
- **`GET` was refused bare, with a number, and with `QPI`'s answer.**

## What followed in the tools

- **The interpreter follows the rows.** `MOD` sits with `*` and gives the
  floored remainder; `NTHROOT` binds tighter than `*`, takes odd roots of
  negatives and refuses even ones; a list read at 0 answers its last element
  and one assigned at 0 appends; a matrix read at 0 raises. What is still not
  measured raises: `MOD` beside `/`, `NTHROOT` beside `^`, an empty list at 0.
  `test_interp.py` from 114 to 124.
- **The linter's `one-based` warning is a measured hazard now**, labelled
  `emulator`, and says what a 0 does to a list and to a matrix. It stays a
  warning: on a list the code runs.
- **`tools.md`, `AGENTS.md`, the paste block and steps 2 and 6 of the guided
  path** say what was measured instead of "not measured".

## Deviations

- **The effect probe for `Base` taught nothing new.** It set `Base` to 3,
  the value it already held. What 0, 1 and 2 give is still open, and the
  entry says so.
- **`DelHVars` was refused, and the row does not say at which step**: making
  `ZQ` with `EXPR("ZQ:=5")`, counting, deleting or counting again.
- **The `L(0)` row measured a computed index.** Whether a literal `L(0)` in
  the source compiles is a compile question, and goes to 08.1-04.
