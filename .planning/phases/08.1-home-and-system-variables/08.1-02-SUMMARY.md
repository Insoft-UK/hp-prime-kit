# Plan 02 summary: the app's mode and numeric view, and the four questions batch 1 raised

## What was run

One batch of 46 calls on the Virtual Calculator 2.4, build 2025-09-15, on
2026-09-24, with the Function app active. All 46 read back.

## What was built

- **16 entries**: `AAngle`, `AComplex`, `ADigits`, `AFormat` in
  `common-app-mode`, and `NumStart`, `NumStep`, `NumType`, `NumZoom`,
  `NumIndep`, `AFiles`, `AFilesB`, `ANote`, `AProgram`, `AVars`, `DelAVars`
  and `DelAFiles` in `common-numeric-view`. Each says it was measured with the
  Function app active.
- **Two new facts**, both `emulator`: `apps.app-angle-overrides-home`,
  renamed in 08.1-03, before it was published, to
  [apps.app-mode-overrides-home](../../../docs/topics/apps.md#apps.app-mode-overrides-home)
  once batch 3 showed the complex setting and the number format behave the
  same; and
  [ppl.string-index-code](../../../docs/topics/ppl.md#ppl.string-index-code).
- **`Base`, `HComplex`, `HAngle`, `MOD`, `NTHROOT` and `ppl.one-based`**
  carry the new rows. The paste block gained a rule for the string, cited.

## What the rows said

- **The active app's angle mode overrides Home's.** With the Function app's
  `AAngle` at 2, `SIN(90)` answered 1, degrees, while `HAngle` stayed at
  radians; at 1 it answered the sine of 90 radians. The same program gives a
  different answer depending on the app.
- **A string indexed answers the character's code**: `"abc"` at 2 is 98.
  The interpreter answered `"b"` until this row.
- **`MOD` sits with `/` as with `*`**, left to right: `8 / 2 MOD 3` is 1 and
  `9 MOD 4 / 2` is 0.5.
- **`NTHROOT` binds tighter than everything**, `^` and a minus sign
  included: `2 ^ 3 NTHROOT 8` is 4 and `-3 NTHROOT 8` is −2; two in a row go
  left to right.
- **`Base` 0, 1, 2 and 3 are binary, octal, decimal and hexadecimal.**
- **With `HComplex` at 1, `2 NTHROOT (-4)` is `2*i`**, and the odd root of a
  negative stays real.
- **An empty list and a string read at 0 are errors.**
- **`DelAVars` and `DelAFiles` called bare were refused.** The numeric view
  reads 0, 0.1, 0, 2 and `{}` on a reset calculator, and every setting tried
  could be set by a program.

## What followed in the tools

- **The interpreter follows every row.** `MOD` beside `/` and `NTHROOT`
  beside `^` are no longer refused, since both are measured, and the code
  that refused unmeasured groupings is gone. A string indexed answers the
  code; an empty list and a string read at 0 raise. `test_interp.py` from 124
  to 128.

## Deviations

- **The run gave up after 30 minutes with the emulator still open.** The
  saved state had moved -- `Check` saves it -- but `M9.hpmat` on disk was
  the 1x1 matrix of a reset calculator, so the batch had not been written. A
  watcher polled for a matrix of the batch's size and collected it when the
  window closed. The harness's 30-minute wait is short for a person who steps
  away; whether to lengthen it is a decision about the tool, not taken here.
- **Three entries first claimed more than the rows show, and were corrected
  before the checks ran.** `AComplex`, `ADigits` and `AFormat` said a
  program or `STRING` does not follow them. But `AAngle`'s values are
  shifted by one against Home's -- 0 as Home, 1 radians, 2 degrees, where
  `HAngle` has 0 radians and 1 degrees -- so 1 is likely the app's "off" or
  "standard", and the rows that set 1 could not have shown a change. The
  entries now say what was measured and why it does not settle the question;
  the Finance app's two decimals point the same way.
- **`NumZoom` was set to 2, the value it held**, so its row shows the
  assignment accepted and nothing more, as `Base` did in batch 1.
