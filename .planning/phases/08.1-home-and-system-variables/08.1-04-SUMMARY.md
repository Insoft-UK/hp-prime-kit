# Plan 04 summary: the questions only a compiler answers

## What was built

- **`hpprime examples --compile FILE`.** Programs headed `[fact] NAME` go on
  `Prime_1` with `HPKDOC` and two controls, `ZCOK` and `ZCBAD`; the person
  presses `Check` on each in the printed order; after the window closes each
  file says whether it compiled, by its compiled block. If a control comes
  out wrong nothing is concluded or stored. Twelve tests with a stand-in
  emulator; `tools.md` explains it.
- **A bug in it, found before the session**: the file's own `#` comments
  were attached to the program before them, which would have made that
  program fail for a reason that was not the question. A comment line now
  belongs to no program, and a test holds it.

## What was run

22 programs and 15 calls on the Virtual Calculator 2.4, build 2025-09-15, on
2026-09-24. A first attempt was abandoned when the person lost the order; it
stored nothing, and resetting `Prime_1` removes every program before the
next. The second attempt's window stayed open after the person closed what
they took to be it; a close request to that window's process alone, by the
lock that names it, let it save. **Both controls came out right**, so all 22
answers are stored.

## What the answers said

| Question | Answer |
|---|---|
| 9, 10, 11, 12 variables in one `LOCAL` | none compiles: the limit is 8 |
| 2, 4, 6 initialised variables in one `EXPORT` | all compile |
| a `LOCAL` after code in a nested block | compiles, and works |
| a function's own `END` without `;` | does not compile, last in the file or not |
| `ENDCASE`, `ENDFUNC` | do not compile |
| a literal `zl(0)` | compiles, and answers 30, the last element |
| `za = 2;` as a statement | compiles and assigns nothing: answers 1 |
| three locals initialised on one line | compiles, answers 6 |
| `LOCAL i`, `LOCAL e` | both work: 6 and 3 |
| a call to the program's own function, or another program's, indexed | does not compile |
| a program exporting `AREA` | compiles, and `AREA(2)` on Home answers 12.566, the program's: it hides the Function app's |
| two syntax errors at lines 4 and 12 | `Check` named line 4, the first, read off the screen by the person |
| `WAIT(-1)` twice, timed with `TICKS` | waited both times, 17.6 s and 13.9 s, and answered 42, the key `1` |

## What followed

- **Facts**: `ppl.local-limit` is now "at most 8"; `ppl.check-last-error`
  says the named line depends on the kind of error, since this contradicts
  its old title; `ppl.i-e-as-locals` went from `unverified` to `emulator`;
  `interface.wait-minus-one` from `unverified` to `emulator`, the G2
  exception kept as unexplained; `ppl.equality-operators`,
  `ppl.end-semicolon`, `ppl.no-end-keywords`, `ppl.index-call`,
  `ppl.locals-at-top`, `ppl.export-initialised`,
  `ppl.locals-initialised-one-line`, `ppl.one-based` and
  `ppl.global-namespace` carry the answers.
- **The linter**: `local-limit` an error from 9; `end-semicolon` an error on
  a function's `END`; `single-end` an error for `ENDCASE` and `ENDFUNC`;
  `local-first` and `export-multiple` stop flagging what compiled; the
  `index-call` warning on a name the file does not define is labelled
  `emulator`; and a new rule, `equality-statement`, warns on `x = 2;`.
  Thirteen rules. `test_lint.py` from 62 to 66.
- **The interpreter refuses to load what does not compile**: 9 or more
  variables in one `LOCAL`, a function's `END` without `;`, and 7 initialised
  variables in one `EXPORT`. `test_interp.py` from 128 to 135.
- **The guided path, `AGENTS.md` and the paste block** say "at most 8", warn
  about `x = 2;`, and no longer say `Check` names the last bad line.

## Deviations

- **`ENDPROC` was not in the session**, so `single-end` still warns on it as
  `unverified`. Nor were 3 and 5 initialised variables in one `EXPORT`,
  which are no longer flagged because 2, 4 and 6 compiled.
- **Only `1` was pressed during the `WAIT(-1)` calls.** Asked afterwards,
  the person said the `[Enter]` was the one that started `HPKDOC`, which then
  waited until `1`. Whether other keys, or an `[Enter]` pressed during the
  wait, end it the same way was not tried, and the fact says so.
