# Phase 8.1 context: Home and system variables, and the open questions

## What this phase is

Two jobs in the same sessions on the emulator. The 65 names HP's list files
as `variable`, and `GET`, get entries: Home's settings, the system's, and the
settings every app shares. And the open questions every program runs into
are measured, so that the linter's `unverified` warnings become errors or go.

Inserted on 2026-09-16; moved ahead of the rest of Phase 8 and given the open
questions at the user's choice on 2026-09-24.

**`GET` is on the list because a release note names it.** The notes of 2.2
say it behaves consistently on what `QPI` answers; no source says what it is,
and the list gives it no group, which an entry needs for its folder.

**Some of these are commands, not values.** `DelAVars`, `DelAFiles` and
`DelHVars` delete things; `HVars`, `AVars` and `AFiles` answer lists of
names. A batch runs on `Prime_1`, reset before every batch, so deleting there
costs nothing.

**Some settings change how every later answer comes back.** The harness
turns each answer into text with `STRING`, so a batch that sets `HFormat` or
`HDigits` changes the text of every row after it -- the way the Finance app
turned every number into two decimals
([apps.finance-shows-two-decimals](../../../docs/topics/apps.md#apps.finance-shows-two-decimals)).
A probe that sets one has to come last in its batch, or put it back.

**The app-shared settings answer for whichever app is active**, and a reset
calculator has the Function app active
([apps.reset-leaves-function-active](../../../docs/topics/apps.md#apps.reset-leaves-function-active)).
So an untouched batch reads the Function app's `Xmin`.

### The open questions

What `hpprime lint` warns on as `unverified`, since 9704074:

1. a call indexed on a name the file does not define, `F(2)(1)`
2. 9 to 12 variables in one `LOCAL` (8 compiles, 13 fails)
3. 2 to 6 initialised variables in one `EXPORT` (7 fails)
4. a `LOCAL` after code inside a nested block
5. a function's own `END` without its `;`
6. `ENDCASE`, `ENDPROC` and `ENDFUNC`
7. an index of 0 into a list or a matrix

The open halves of the facts in `ppl.md`, and what Phase 9.1 left:

8. `a = 2;` as a statement: compiles? assigns, or compares and drops it?
9. three locals initialised on one line (two compiled)
10. `LOCAL i` and `LOCAL e`, and arithmetic with them
11. `Check` naming the last bad line, confirmed with two errors far apart
12. a program exporting a name an app already has, such as `AREA`
13. how `MOD` and `NTHROOT` bind against `+`, `-`, `*`, `/` and `^`
14. `-9 MOD 4`, and `NTHROOT` of a negative number
15. whether the calculator ignores case in a command's name, which the
    linter assumes it might (the Phase 2 decision)
16. whether `WAIT(-1)` waits for a key, which two measurements contradict

**They split three ways by how they can be measured.**

- **In a batch** (7, 13, 14, 15): the answer comes back as a row. Each
  doubtful form goes inside `EXPR`, so a refusal costs its row.
- **Does it compile?** (1 to 6, 8 to 11): a batch cannot ask, because a
  program that does not compile refuses the whole batch. Each needs a small
  program of its own and the editor's `Check`. The emulator writes a
  program's compiled block back into its file once it compiles
  ([deploy.emulator-folder](../../../docs/topics/deploy.md#deploy.emulator-folder)),
  so the tool can tell which compiled by reading the files after the window
  closes: nobody has to write down what `Check` said.
- **By hand, watching the screen** (12, 16): `AREA(2)` typed on Home, and a
  program that waits.

## Decisions

The user chose 1 to 4 on 2026-09-24, each the recommended option, and all
sixteen questions; 5 to 7 were approved with the context.

1. **Read, set, and the effect.** Read every one; set and read back
   the ones a program would set -- the settings and the plot and numeric
   windows -- and give each Home setting one probe of what it changes, such
   as `HAngle` against `SIN(90)`. The commands that delete are called once
   each, on the throwaway calculator. Chosen over reading and setting only,
   which would leave `HAngle`, `HDigits` and `HFormat` without saying what
   they change, and over reading only.
2. **The Function app is active for the shared settings.** It is the state
   a reset calculator is in, and each entry says so; a second app only where
   the Function app refuses. Chosen over a second batch with another app
   selected by hand.
3. **Compile questions by small programs and `Check`.** The tool installs
   one small program per question on the emulator, with two controls, one
   known to compile and one known to fail; the user presses `Check` on each
   and closes the window; the tool reads which ones compiled from their
   files. Chosen over the user reading out each `Check`, and over leaving the
   compile questions open.
4. **All sixteen open questions**: the linter's seven, the five halves of
   `ppl.md`, the three Phase 9.1 left, and `WAIT(-1)` by hand.

Approved with the context:

5. **`GET` goes in a folder of its own, `other`**, for a name whose group the
   sources do not give; the list is given that group by its extractor. The
   probes are `GET` bare, `GET(1)` and `GET("A")` in `EXPR`, and the entry says
   what came back, or that it is on HP's list and refused, as `ALPHA` does.
6. **The plans follow the sessions**, one batch each:
   - **08.1-01** Home's settings, the system's, `Ans` and `GET`: 20 names,
     with the batch questions 7, 13, 14 and 15 in the same batch
   - **08.1-02** the app's mode and numeric view: 16 names
   - **08.1-03** the plot view: 30 names
   - **08.1-04** the compile questions, and the two by hand
7. **A setting that changes how answers come back is set last** in its batch,
   and the rows after it are read knowing that.

## Answered so far

08.1-01, 2026-09-24: questions 7 (at run time), 13, 14 and 15. Their answers
raised four more, for the next batches: `MOD` beside `/`; `NTHROOT` beside
`^` and after a minus sign; an even root of a negative with `HComplex` at 1;
and what `Base` 0, 1 and 2 give. Whether a literal `L(0)` compiles joins the
compile questions of 08.1-04.

08.1-02, 2026-09-24: all four answered. It raised two, for 08.1-03 or later:
what `AComplex`, `AFormat` and `ADigits` do at 2, if the app's values are
shifted by one against Home's as `AAngle`'s are; and whether another app's
`AAngle` overrides Home's the same way.

08.1-03, 2026-09-24: the first answered -- they are shifted, and each
overrides Home's once it is not 0. The second stays open: a batch cannot
select an app. Every name of the phase now has an entry, so 08.1-04 is the
compile questions and the two by hand.

## Success criteria (from the roadmap)

1. Every name the list files as `variable` has an entry in the fixed format,
   with what it holds and whether a program can set it
2. `GET` has an entry, which says what it is, or that the sources do not say
3. Every example in those entries has a Virtual Calculator result on file, or
   says why it cannot have one
4. Every case `hpprime lint` warns on as `unverified`, and every open half of
   a fact in `ppl.md` that a program can run into, is measured on the
   emulator or says why it cannot be
5. A lint case that is measured becomes an error with its evidence, or leaves
   the linter, and its test says which
