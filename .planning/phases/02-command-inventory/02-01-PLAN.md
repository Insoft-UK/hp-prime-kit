<objective>
Put the list of every PPL name in the repository as data, built from three
sources by a maintainer's script, and make the documentation's index cover
the whole list, so it shows at every moment how much of PPL is documented.
</objective>

<context>
@.planning/phases/02-command-inventory/02-CONTEXT.md
@tests/hp_examples_extract.py   (how a maintainer's extraction is written here)
Sources, kept outside the repository:
- Command Tree 13217, as text (pdftotext -layout). A topic title sits in a
  left column, its help text in a right one; a line's left part ends at the
  column where the page's "Help Text" header starts, and a title is
  separated from the text by two or more spaces.
- CommandsList.txt from commandslist.zip, Windows-1252. One row per name:
  optional number, the name, HP's menu path (Toolbox, Program, Apps...),
  `|`, a description that is not copied. 924 rows; 371 have no menu (they
  are in the Catalog only). Names with an arrow were exported with `?` in
  its place (`C?PX`) and are matched back to the 13217 spelling.
- release_info.txt from the 2.4.15515 firmware package, UTF-8. One section
  per version from 2.4 back to 13333; the sections after 2.1.14091 are the
  ones that can add names the other two do not have.
</context>

<tasks>

<task type="auto">
  <name>Task 1: The extraction, and the list</name>
  <files>tests/names_extract.py, docs/commands/names.tsv</files>
  <action>A maintainer's script, standard library only, that takes the three
  files as arguments and writes the list: one line per name, tab-separated,
  with a header: name, kind, group, menu, syntax, source. Kinds: statement,
  keyword, command, function, app function, app variable, variable, CAS.
  The group is HP's menu, lower case (strings, drawing, matrix, loop...).
  Syntax is the first syntax line HP's help gives for the topic, when it
  gives one. Source is 13217, 2.1.14181, or the release-notes version that
  names it. Operators and the templates' variants (FOR STEP, IF THEN ELSE)
  are folded into their statement. The docstring says how to get each
  source, like tests/hp_examples_extract.py.</action>
  <verify><automated>python tests/names_extract.py ct.txt CommandsList.txt release_info.txt > docs/commands/names.tsv</automated></verify>
  <done>The list exists; its counts per kind and per source are printed and
  recorded in the summary; every name in the interpreter's BUILTINS is on
  it.</done>
</task>

<task type="auto">
  <name>Task 2: Reading the list, and the index over all of it</name>
  <files>hpkit/names.py, hpkit/docs.py, docs/commands/index.md,
  docs/format.md, tests/test_reference.py</files>
  <action>hpkit/names.py reads the list (by name, by kind, by group; app
  names with and without their app). hpkit/docs.py then: builds the index
  from the list, every in-scope name with its group and kind, linked with
  its summary and weakest label when it has an entry, "no entry yet" when
  not, and a count of the CAS names known and not documented; reports an
  entry whose name is not on the list, and an entry whose folder is not a
  group on the list. Sample entries move if their folder is not HP's group
  name. docs/format.md says where the list is and what it holds.
  test_reference gains a break for each new problem.</action>
  <verify><automated>python tests/run_all.py</automated></verify>
  <done>The index covers the whole list, the entries all sit on it, and the
  suite passes with the new breaks caught.</done>
</task>
