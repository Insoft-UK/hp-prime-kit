<objective>
Make the linter catch the most common thing a model invents: a command that
does not exist. It knows every name from the documentation's list, and every
name the program itself defines.
</objective>

                  emptied; exports collected for --set)

</context>

<tasks>

<task type="auto">
  <name>Task 1: The unknown-name rule</name>
  <files>hpkit/lint.py</files>
  <action>Collect what each file defines: its functions, exported or not,
  and their parameters; its LOCAL and EXPORT variables and other global
  declarations. Known besides: every name on the list, and the calculator's
  variables (A to Z, θ, L0 to L9, M0 to M9, G0 to G9, Z0 to Z9 and those the
  list gives). Then flag every `NAME(` in code that is none of these, as
  unknown-name: WARN when the file is linted alone, ERROR with --set, where
  the definitions of all the files are collected first. Replace BUILTINS
  with the list in the one-based rule.</action>
  <verify><automated>python tests/test_lint.py</automated></verify>
  <done>The rule runs on every file, and the existing cases still
  pass.</done>
</task>

<task type="auto">
  <name>Task 2: Its cases, both directions</name>
  <files>tests/test_lint.py</files>
  <action>Cases it must catch: STRLEN(s) in a file on its own (a warning)
  and with --set (an error). Cases it must stay quiet on: a call to the
  file's own function, exported and not; a parameter or a local list
  indexed as L(2); an exported variable; L1(2) and M1(1,2); an app function
  with and without its app; a CAS name; with --set, a call to a function
  exported by the other file.</action>
  <verify><automated>python tests/run_all.py</automated></verify>
  <done>Every case passes, and the kit's own examples and templates lint
  with no unknown-name.</done>
</task>
