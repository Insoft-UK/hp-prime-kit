# Phase 9.1 verification: Tools that keep their promise

Counted on 2026-09-24, after plans 01 and 02, by running each case.

## Criterion 1: `hpprime run` answers correctly or raises with a message, never a partial answer or a traceback

| Case | Before | Now |
|---|---|---|
| `RETURN 9 MOD 4 + 100;` | 9, the linter clean | raises: the binding is not measured |
| `9 MOD 4` | 9, the rest dropped | 1, as on the emulator |
| `(9 MOD 4) + 100` | the whole file refused to load: "expected OP, found ID 'MOD'" | 101 |
| `MOD(9,4)` | 1, a form the calculator refuses | refused with the calculator's reason |
| `3 NTHROOT 8` | 3 | 2, as on the emulator |
| `NTHROOT(3,8)` | refused as a name it did not know | refused with the calculator's reason |
| `RETURN 9 FOO 4;` | 9 | raises, naming `FOO` |
| `CONCAT({1,2,3},4)` | Python `TypeError` | "CONCAT given a list, a number is not covered" |
| `FLOOR({3.2})` | Python `TypeError` | "FLOOR given a list is not covered" |
| `--call "F() F()"` | the first call's answer | refused |

Each has a case in `test_interp.py`, and `hpprime run` exits 1 on each
refusal with one line.

## Criterion 2: a probe whose call holds a stored answer is refused, unless told to replace it

A different answer at collect time leaves the stored row, shows `KEPT` with
the stored answer, and exits 1; `--collect --replace` writes it. A probe on a
stored call is refused before the emulator opens. Both in
`test_examples_run.py`.

## Criterion 3: an unreadable answer costs its row; the two infinities are read

Both infinities decode from the bytes the emulator wrote; three near misses
are still refused. A batch with a bad number cell and a bad text cell stores
the first row from its text and leaves out the second. In `test_numbers.py`
and `test_examples_run.py`.

## Criterion 4: a stored row carries the date its batch ran

A matrix dated 2026-01-02 by hand gives rows dated 2026-01-02.

## What was not checked here

No batch was run on the emulator in this phase: every case above uses a
stand-in matrix. The first real batch of Phase 8.1 is the first run of the
new code against the Virtual Calculator.
