# Plan 01 summary: the interpreter answers as the calculator does, or says it does not cover the case

## What was built

- **A statement ends at `;`, at the keyword that closes its block, or at the
  end of the file.** A word the parser cannot read after an expression no
  longer starts a new statement: the statement it follows becomes one that
  raises "not covered" when it is reached, naming the word and its line.
  The rest of the file still loads and runs. That is what turned
  `RETURN 9 MOD 4 + 100;` from 9 into a refusal.
- **`MOD` and `NTHROOT` as the calculator writes them.** `9 MOD 4` answers 1
  and `3 NTHROOT 8` answers 2, the two answers the emulator gave; `MOD(9,4)`
  and `NTHROOT(3,8)` are refused with the calculator's reason, where the
  interpreter used to answer the first. The two entries now say "Runs on the
  PC: yes", and their three examples run through the interpreter and agree:
  94 examples run on the PC, from 91.
- **A builtin handed something it was not written for raises "not
  covered"**, naming the builtin and the kinds of its arguments. Every
  builtin is called through one method, and so are the arithmetic operators
  and the minus sign. The eight HP examples that used to end in a Python
  `TypeError` now show as notes such as "CONCAT given a list, a number is not
  covered".
- **`hpprime run` never prints a traceback**: a file it cannot load, a call
  it does not cover, and a `--call` with anything after its expression each
  give one line and exit 1. `EXPR` refuses the same leftover text.
- **Tests**: `test_interp.py` from 99 to 114: the five forms that answer,
  eight that must be refused, a file whose uncovered function leaves the
  others running, and the command line never raising.

## Deviations

- **`9 MOD 4 + 100` is refused, not answered 101.** The plan first said 101.
  That assumed `MOD` binds before `+`, which nothing on file measures: had
  the calculator grouped it the other way, the answer would be 9. So the
  interpreter answers only what was measured. Mixed with `+`, `-`, `*`, `/`
  or `^` and no parentheses it raises, and `(9 MOD 4) + 100` answers 101.
  Against a comparison it binds tighter, so `n MOD 2 == 0` works; the
  entries label that the interpreter's assumption. The binding goes to Phase
  8.1's list.
- **A construct not covered no longer stops the file from loading.** The
  first version raised while parsing, so one function using `MOD` with a `+`
  made every function in its file unusable, and the command line printed a
  traceback. It now becomes a node that raises when reached.
- **`--call` and `EXPR` had the same hole as the statements**, parsing one
  expression and dropping the rest. Both now refuse leftover text.
- **`NTHROOT` had no builtin at all.** It computes only a non-negative
  number with a positive degree; the rest raise, since nothing was measured
  there.
