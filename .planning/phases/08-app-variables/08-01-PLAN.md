# Plan 01: the probe that decides the shape of every later batch

## Why a probe and not a batch of entries

172 names at three rows each is 516 rows against the 623 the whole file
holds. Before spending that, four things have to be known, and none of them
is known now. Each is worth more than the rows it costs.

| question | why it decides the plans | cost |
|---|---|---|
| can a variable be read with no app active? | if yes, most of the phase runs unattended; if no, every group needs the user at the keyboard first | 11 rows |
| do the 22 non-ASCII names survive into a program? | if not, a fifth of the phase needs another route entirely | 3 rows |
| can a variable be set, and does the set stick? | decides whether an entry can say "a program can set it", which the success criterion names | 6 rows |
| is `SOLVE` the callable form `Solve` never had? | would close the one group of Phase 7 that answers nothing | 4 rows |

Four more rows go to the case-colliding names and to two variables that
should hold a list rather than a number, which tests the type column.

## The batch

28 calls, every one wrapped in `EXPR` so a bad one costs its own row and not
the batch
([the technique from Phase 6](../06-home-functions/06-CONTEXT.md)). No app is
selected: the harness cannot select one, so this batch measures the
no-app-active condition by construction, which is the baseline every later
round is compared against.

**Reads, one per group** -- `PMT`, `Alpha`, `MeanX`, `MeanY`, `AngleA`,
`NumXStart`, `Root`, `Col`, `LSystem`, `SeqPlot`, `SOLVE`.

**Non-ASCII through the calculator's own channel** -- `ΣX`,
`σX`, `μ₀`. The editing channel was measured on
2026-09-14 and carries all seven codepoints of this phase in both file names
and content; the calculator's own channel is a different one and has not been
measured.

**Set and read back** -- `AngleA:=30`, `Alpha:=0.05`, `ColWidth:=40`, each
followed by a parenthesised read. The parentheses are there for a reason:
`results.tsv` keys on the exact call text, so reading back as `AngleA` would
overwrite the first read and destroy the before-and-after.

**`SOLVE` four ways** -- `SOLVE(X^2-4=0,X)`, the same with a guess,
`SOLVE(E1,X)` against the app's own equation variable, and `SOLVE( )` for
the app-state form.

**The rest** -- `Slope` and `SignedArea` for the case collision, `LSolution`
and `Xlist` for the type column.

## What each outcome means

- **Reads answer**: the phase can run in big unattended batches, and the
  first real plan is one batch a group.
- **Reads refuse**: every group needs its app selected by hand first, as the
  Function app did in Phase 7, and the phase becomes 11 rounds with the user
  at the keyboard. Say so plainly rather than treating the refusals as a
  property of the names.
- **Some answer and some refuse**: the most likely outcome, given `F1`
  answered and `S1` refused. The split itself is then the finding, and it
  should be measured against which apps have state and which do not.
- **`SOLVE` answers**: `Solve` gets its entry corrected the same day, and
  Phase 7's one silent group stops being silent.

## What this plan does not do

It writes no entries. Nothing in `docs/commands/` changes until the rows are
in, which is the order Phase 7 fixed: batch first, then write.
