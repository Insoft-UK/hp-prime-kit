# Plan 04: the Finance app, whose functions never needed it

## Why Finance, and why this order

Finance holds 68 of the 110 app variables still without an entry. It is also
the one large app whose **functions** answered without it: 30 of its 34 did,
in Phase 7, from batches nobody had touched -- which means with the Function
app active,
[apps.reset-leaves-function-active](../../../docs/topics/apps.md#apps.reset-leaves-function-active).
Every other app measured so far gates both its functions and its variables.
So the question here is sharper than volume: in an app whose functions do not
need it, do the variables?

## The batch

One batch, **with no app selected**, so it costs the user nothing beyond
running it:

- **all 68 Finance variables**, read once each;
- **five Inference lists** -- `Ylist`, `ObsList`, `ExpList`, `ProbList`,
  `ContribList` -- as controls. With the Function app active they are
  foreign. `Xlist` answered under three foreign apps and nothing else has been
  tried that way; these five decide whether it is alone.

Every call text is generated against the keys already in `results.tsv`, never
typed, after round 5 overwrote a stored row by reusing `(Alpha)`.

## What each outcome means

- **Finance variables answer**: this app gates neither functions nor
  variables. The rule becomes "some apps gate, some do not", and which is
  which has to be stated per app rather than assumed. The group can be written
  from this one batch.
- **They refuse**: the variables are gated even where the functions are not,
  and a second batch with the Finance app selected by hand measures them.
- **The five lists answer**: `Xlist` is not special -- empty lists, or this
  app's lists, can be read from anywhere -- and its entry is corrected.
- **They refuse**: `Xlist` is alone, and its entry says so with five
  neighbours as evidence rather than none.

## What this plan does not do

It writes no entries until the rows are in. It does not change the harness:
the guard against overwritten rows is a decision still waiting for the user.
