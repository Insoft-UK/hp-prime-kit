# Plan 05: whether a program reaches another app's variable by its app's name

## Why this first

The 42 variables left belong to seven apps: statistics-1var 16,
statistics-2var 12, advanced-graphing 6, spreadsheet 4, linear-solver 2,
sequence 1 and solve 1. The rule so far is that an app's variables answer
only while their app is active, variable by variable
([apps.function-needs-active-app](../../../docs/topics/apps.md#apps.function-needs-active-app)),
and a batch cannot select an app: the person does, by hand, before each
batch. Seven apps would be seven such rounds.

PPL also has a qualified form, `Function.Xmin`, with the app's name in front,
which `docs/format.md` uses for identifiers. Nothing here has measured
whether a program can use it: whether `Statistics_1Var.MeanX` answers while
the Function app is active. If it does, the whole group runs with nobody
selecting anything, and a program reading another app's results without
switching to it is something every such program needs to know. The user
chose to probe it first, on 2026-09-25.

## The batch

One batch, **with no app selected**, so the Function app is active
([apps.reset-leaves-function-active](../../../docs/topics/apps.md#apps.reset-leaves-function-active)).
In order, since some rows change state:

1. **Four controls, whose unqualified form is on file.** `Function.Xmin`,
   whose app is active: if this refuses, the qualified form does not work
   through `EXPR` at all. `Triangle_Solver.AngleA`, `Inference.Alpha` and
   `Finance.PV`, all three refused unqualified with the Function app active:
   an answer from them shows the qualified form lifts the app rule, and
   that the apps with one-word names and those with two are named as
   written here.
2. **All 42, qualified**, read once.
3. **The same names unqualified**, for the 32 that have no such row yet: the
   refusal the qualified form is compared against. The other ten already
   have it.
4. **Statistics 1Var with data.** `D1` set to `{1,2,2,3,7}`, `Do1VStats` run
   on `H1`, then each of its 16 variables read again. Each such row sets the
   data and runs the command itself, so it states its own condition and does
   not depend on the rows before it.
5. **Statistics 2Var with data.** `C1` set to `{1,2,3,4}`, `C2` to
   `{2,3,5,9}`, `Do2VStats` run on `S1`, then its 12 variables and `MeanX` and
   `ΣX` read again: whether those two follow the app they are read through.
6. **The Linear Solver**: `LSystem` set to `[[2,1,5],[1,-1,1]]`, the system
   `LinSolve` answered `{2,1}` for, then `LSolution` read.
7. **`SOLVE` qualified, called** as HP's list writes it.

Every call text is generated and checked against the keys `results.tsv`
already holds, and the harness refuses a batch that reuses one.

The data is chosen so that the candidates are told apart: for `{1,2,2,3,7}`
the mean is 3 and the median 2, the sum of squares about the mean 22, the
sample deviation 2.34520787991 and the population one 2.09761769634. For the
pairs, `Corr` is 0.959166304663 and its square 0.92.

## What each outcome means

- **The controls answer and so do the 42**: the rest of the phase runs
  unattended. A second batch asks whether a program can set each of the 42,
  through the same form. The qualified form becomes a fact in `apps.md`, and
  its evidence names these rows.
- **The controls answer and some of the 42 refuse**: those refuse for their
  own reason, as nine Finance variables did with Finance selected, and the
  entries say so.
- **`Function.Xmin` answers and the other three refuse**: the qualified form
  exists and does not lift the app rule. The rest is one batch per app, the
  person selecting it first, and the fact says the form is no shortcut.
- **`Function.Xmin` refuses**: the form does not work through `EXPR`, which
  is how every row here is taken, and that is all this batch can say. Then
  one batch per app.

## The second batch, designed on the first's answer

The first batch answered: the four controls and 28 of the 42 answered
qualified with the Function app active; the 14 that refused -- the twelve
Statistics 2Var results, `LSolution` and `SOLVE` read bare -- answered once
their app had data or, for `SOLVE`, were called. So the second batch, again
with no app selected:

1. **Two programs that write the form in their source**, not through
   `EXPR`, since that is how a program uses it: `ZQREAD` returns
   `Triangle_Solver.AngleA`; `ZQSTAT` sets `Statistics_1Var.D1`, runs
   `Do1VStats` and returns `MeanX`. The person checks each, with the two
   controls, and `HPKDOC` calls them.
2. **Whether a program can set each of the 42**, qualified: read, assign,
   read back, put back. A refused assignment answers `refused`, and a
   refused put-back does not hide it. The statistics results and
   `LSolution` are assigned after their data, the others as a reset leaves
   them.
3. **Three functions refused unqualified with the Function app active**:
   `Triangle_Solver.SSS(3,4,5)`, `Spreadsheet.SUM({1,2,3})` and
   `Solve.Solve(X^2-4=0,X,1)`. `Do1VStats` answered qualified in the first
   batch; these say whether that holds for functions in general.

## What this plan does not do

It writes no entries until the rows are in, and it does not ask yet whether
a program can set these variables: that batch is designed on this one's
answer.
